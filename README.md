# ntx

`nerd text server`

A self-hosted personal site server. Blog, content sections, admin
UI - configured via a single TOML file and HTML templates you
supply. 

One process can serve several websites, routed by Host header, each with its
own content, templates and admin password.

Dynamic option works with sqlite or postgresql to suit your needs.

Can also be used to generate a static site for deployment anywhere.


## Install binary

**Homebrew (macOS/Linux):**

```sh
brew tap nod/ntx https://github.com/nod/ntx
brew install ntx
```

**Shell script:**

```sh
curl -sSf https://raw.githubusercontent.com/nod/ntx/main/install.sh | sh
```

Installs to `~/.local/bin` by default. Requires a pre-built release binary or Go 1.21+ as a fallback.

```sh
# pin a version
NTX_VERSION=v0.7.1 curl -sSf https://raw.githubusercontent.com/nod/ntx/main/install.sh | sh

# install to a different location
INSTALL_DIR=/usr/local/bin curl -sSf https://raw.githubusercontent.com/nod/ntx/main/install.sh | sh
```

## Quick start

```sh
# generate a starter config — prompts for admin password, auto-generates session_secret
ntx gen-config -p > ntx.toml

# start the server
ntx serve
```

Admin UI is at `/admin`. Blog posts are written in Markdown.

The generated config serves one site on `site_url = "localhost"`, so
`http://localhost:8080/` works out of the box. Change `site_url` to your real
hostname when you deploy — it is the key requests are routed by.

## Commands

| Command | Description |
|---|---|
| `ntx serve` | Start the HTTP server |
| `ntx generate` | Write a static site to `./out` |
| `ntx hash-password` | Generate a bcrypt hash for `ntx.toml` |
| `ntx gen-config` | Print a sample `ntx.toml` with a random session secret; `-p` to also embed a password hash |
| `ntx version` | Print the version and exit |

`ntx generate --out <dir>` and `ntx serve --config <file>` accept flags — run `ntx <command> --help` for details.

## Configuration

Everything lives in `ntx.toml`. Settings at the root configure the process;
each `[[site]]` block configures one website. At least one is required.

```toml
static_path   = "./static"
template_path = "./templates"
db_dsn        = "sqlite://./ntx.db"
bind_addr     = ""         # empty = localhost only; "0.0.0.0" for all interfaces
port          = 8080
dev           = false

session_secret = ""   # auto-generated by ntx gen-config
# global_admin_password_hash = ""   # optional: logs into every site's admin

[[site]]
key                 = "mysite"      # stable id; owns this site's posts and tags
site_url            = "localhost"   # the Host header this site answers on
site_name           = "mysite"
site_description    = "My personal site."
about_slug          = "about"
admin_password_hash = ""   # ntx gen-config -p  or  ntx hash-password
```

See [`docs/ntx.sample.toml`](docs/ntx.sample.toml) for a full annotated example.

## Multiple websites

Add another `[[site]]` block. Requests are routed to a site by matching the HTTP
`Host` header against its `site_url`; an unmatched host gets a 404.

```toml
[[site]]
key                 = "mysite"
site_url            = "mysite.com"
admin_password_hash = "..."

[[site]]
key                 = "othersite"
site_url            = "other.example.com"
admin_password_hash = "..."
template_path       = "./other-templates"   # optional per-site override
static_path         = "./other-static"      # optional per-site override
```

Each site has its own posts, tags and admin session — a session minted on one
site is not accepted on another. Behind a reverse proxy, forward the original
host (`proxy_set_header Host $host;`) or nothing will resolve.

Upgrading from a single-site install? See
[Upgrading from a single-site install](docs/usage.md#upgrading-from-a-single-site-install)
— back up the database first, and the converted `[[site]]` block must use
`key = "default"` to keep your existing content.

## Content sections

Sections are arbitrary URL namespaces backed by static templates — no database involved. They belong to a site:

```toml
  [[site.section]]
  slug  = "projects"
  title = "Projects"
  pages = [
    { slug = "ctfkit", title = "CTFKit", year = "2024" },
  ]
```

`GET /projects/ctfkit` renders `templates/sections/projects/ctfkit/index.html`. Extra keys (`year`, etc.) are passed to the template as top-level variables.

## Static site generation

```sh
ntx generate --out ./out
```

Renders home, blog, and all section pages to disk. Copies static assets. Each site lands in its own `./out/<key>/` directory. Output can be served by nginx, S3, Cloudflare Pages, or any static host.

## Templates

Templates live in `./templates` (configurable globally, or per site with a `[[site]]`-level `template_path`). Every template is parsed with `base.html` as the layout. Set `dev = true` to reload templates from disk on every request without restarting.

See [`docs/usage.md`](docs/usage.md) for the full template directory structure and available template variables.

## Building from source

Requires Go 1.21+.

```sh
just build          # builds ./build/ntx for the current platform
just build-all      # builds linux/darwin × amd64/arm64 into ./build/
just test
just run-dev        # starts server with dev=true
```
