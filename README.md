# ntx

`nerd text server`

A self-hosted site server. Blog, content sections and an admin UI, with
sites created and managed in the browser and their look coming from themes you
supply.

One process can serve several websites, routed by Host header, each with its
own content, sections and theme.

Each site has its own people. A site signs them in with Google or Auth0, and
access is by invitation only: site admins add people or send invite links, and
contributors can be trusted to publish or have their work wait for an admin.

Dynamic option works with sqlite or postgresql to suit your needs.

Can also be used to generate a static site for deployment anywhere.


## Install binary

**Homebrew (macOS/Linux):**

```sh
brew tap nod/ntx https://github.com/nod/ntx
brew trust --formula nod/ntx/ntx   # current Homebrew requires trusting third-party taps
brew install ntx
```

Upgrade with `brew update && brew upgrade ntx`. If you tapped before v0.7.2 and
`brew install` can't find `ntx`, run `brew update` first to refresh the tap.

**Shell script:**

```sh
curl -sSf https://raw.githubusercontent.com/nod/ntx/main/install.sh | sh
```

Installs to `~/.local/bin` by default. Requires a pre-built release binary or Go 1.21+ as a fallback.

```sh
# pin a version
NTX_VERSION=v0.7.1 curl -sSf https://raw.githubusercontent.com/nod/ntx/main/install.sh | sh

# install to a different location
INSTALL_DIR=/usr/local/bin curl -sSf https://raw.githubusercontent.com/nod/ntx/main/install.sh | sh
```

## Quick start

```sh
# generate a config: prompts for the root password, generates the secrets
ntx gen-config -p > ntx.toml

# start the server
ntx serve
```

Open `http://localhost:8080/admin/login` and sign in as **`root`** with the
password you chose. `localhost` is the config's `platform_hostname`: the place
root signs in before any site exists. From there, create a site under **sites**:
give it a key, the hostname it answers on, and a theme. Its admin is then at
`http://<hostname>/admin`. Blog posts are written in Markdown.

To try a second hostname locally, use something like `demo.localhost`, which
most systems resolve to 127.0.0.1.

## Commands

| Command | Description |
|---|---|
| `ntx serve` | Start the HTTP server |
| `ntx generate` | Write a static copy of every site to `./out/<key>/` |
| `ntx hash-password` | Generate a bcrypt hash for `root_password_hash` |
| `ntx gen-config` | Print a sample `ntx.toml` with generated secrets; `-p` also prompts for the root password |
| `ntx version` | Print the version and exit |

`ntx generate --out <dir>` and `ntx serve --config <file>` accept flags; run `ntx <command> --help` for details.

## Configuration

`ntx.toml` holds only server settings. Sites, their sections and their posts
live in the database and are managed in the browser.

```toml
bind_addr          = ""            # empty = localhost only; "0.0.0.0" for all interfaces
port               = 8080
db_dsn             = "sqlite://./ntx.db"
dev                = false
trusted_proxies    = ["127.0.0.1/32", "::1/128"]   # who may set X-Forwarded-*

session_secret     = ""            # generated by gen-config
encryption_key     = ""            # generated by gen-config
themes_path        = "./themes"
platform_hostname  = "localhost"   # where root signs in before any site exists
root_password_hash = ""            # ntx gen-config -p  or  ntx hash-password
```

See [`docs/ntx.sample.toml`](docs/ntx.sample.toml) for an annotated example.
A config from an earlier release (`[[site]]` blocks) is rejected with a pointer
to the docs, and a database from an earlier release must be deleted: there is
no upgrade path.

## Sites

Root creates sites under **sites** in the admin. Requests are routed to a site
by matching the HTTP `Host` header against its hostname; an unmatched host gets
a 404. Each site has its own posts, tags, sections and sign-ins: a session on
one site is not accepted on another. Behind a reverse proxy, forward the
original host (`proxy_set_header Host $host;`) or nothing will resolve.

## Themes

A site's public pages come from a theme: a folder under `themes_path` with
`templates/` and `static/`. This repo ships `default`, `blog` and `nerdtx` in
[`themes/`](themes/). Admin pages are built into the binary and aren't themed.
Template edits show on the next request; no restart needed.

## Content sections

Sections are URL namespaces backed by theme templates, edited per site under
**settings** as JSON:

```json
[{"slug": "projects", "title": "Projects",
  "pages": [{"slug": "ctfkit", "title": "CTFKit", "vars": {"year": "2024"}}]}]
```

`GET /projects/ctfkit` renders the theme's
`templates/sections/projects/ctfkit/index.html`, with `vars` passed to the
template as top-level variables.

## Static site generation

```sh
ntx generate --out ./out
```

Renders every site's home, blog and section pages to disk and copies its theme's
static assets, one `./out/<key>/` directory per site. Output can be served by
nginx, S3, Cloudflare Pages, or any static host.

See [`docs/usage.md`](docs/usage.md) for themes, template variables and deployment.

## Building from source

Requires Go 1.21+.

```sh
just build          # builds ./build/ntx for the current platform
just build-all      # builds linux/darwin × amd64/arm64 into ./build/
just test
just run-dev        # starts server with dev=true
```
